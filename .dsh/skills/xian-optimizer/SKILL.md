# Xian优化器

把「一句话需求」变成「AI 能直接执行的项目级任务书」。

核心不是润色文案，而是三件事：

1. **先理解项目**：技术栈、目录分层、入口、命令、符号、导入关系、测试与 Git 变更。
2. **再定位代码**：把需求映射到具体文件与行号，区分「要改的」「要参考的」「要补测试的」。
3. **最后规范化提示词**：目标、范围、代码位置、约束、步骤、验收标准、验证命令一次给全。

> 索引只是缩小范围的地图，不是事实来源。动手前必须打开候选文件确认符号与行号。

## 何时使用

- 用户说：「给登录页加个记住我」「修一下上传 413」「把订单列表优化一下」——信息不足以直接改代码。
- 用户要求：「先看看项目结构」「定位要改哪里」「把提示词写清楚」「带上代码路径」。
- 需要把中文口语需求转成可交给另一个 AI/子代理执行的 brief。
- 需要在改动前确认影响面、测试点和验证命令。

## 何时不要用

- 用户已经给出精确文件、函数和改法：直接读代码执行，不要多绕一层。
- 纯知识问答、与当前项目无关的通用代码片段。
- 项目根目录无法确定，且用户拒绝提供路径：先问清楚，不要猜。

## 快速开始

技能目录就是本文件所在目录。以下命令中的 `<skill>` 用实际目录替换；在 DSH 中它通常是
`.dsh/skills/xian-optimizer`。

```bash
# 1) 体检：确认根目录、技术栈、命令、Git 状态
node "<skill>/scripts/xian.mjs" doctor --root "<项目根>"

# 2) 优化：把用户原话作为 --prompt，输出可直接粘贴的提示词
node "<skill>/scripts/xian.mjs" optimize \
  --prompt "给登录页面加一个记住我复选框，并调整登录按钮样式" \
  --root "<项目根>" \
  --max-files 8

# 3) 需要结构化结果时
node "<skill>/scripts/xian.mjs" optimize \
  --prompt "<用户原话>" --root "<项目根>" --json --quiet
```

PowerShell 中若原话含引号，使用单引号包裹，内部单引号写成 `''`：

```powershell
node "<skill>\scripts\xian.mjs" optimize --prompt '修复上传大文件时报 413' --root "E:\my-project" --json --quiet
```

常用参数：

| 参数 | 作用 |
| --- | --- |
| `--root <目录>` | 项目根；缺省从当前目录向上找 `.git` |
| `--max-files <3-15>` | 最多定位多少个文件，默认 8 |
| `--max-chars <n>` | 提示词长度上限，默认 16000 |
| `--json` | 输出结构化 JSON（含 `prompt`、`files`、`warnings`） |
| `--out <文件>` | 写入文件；不加时只打印 |
| `--refresh` | 忽略 30 秒索引缓存，强制重扫 |
| `--quiet` | 不输出 stderr 摘要 |

## 标准工作流

### 第 1 步：确定项目根

优先级从高到低：

1. 用户明确给出的目录。
2. 当前会话工作目录（`cwd`）。
3. `git rev-parse --show-toplevel`。
4. 从 `cwd` 向上找 `.git`。

不要对 `C:\`、用户主目录或包含多个项目的父目录直接扫描；先缩小到具体仓库。

### 第 2 步：运行优化器

把**用户原话原样**传给 `--prompt`，不要先自行改写。优化器需要原话来判断意图、同义词和范围。

```bash
node "<skill>/scripts/xian.mjs" optimize --prompt "<用户原话>" --root "<项目根>" --json --quiet
```

读取 JSON 中的：

- `prompt`：最终提示词，可直接作为任务 brief。
- `files[]`：`path`、`line`、`role`（primary/likely/reference/test/config）、`reasons`。
- `confidence`：高/中/低。
- `warnings`：索引截断、无 Git、未命中、输出截断等。
- `project.commands`：构建、测试、lint、类型检查命令。

### 第 3 步：核对定位（必须）

对 `files[]` 中每个 `role` 为 `primary` / `likely` 的条目：

1. 用 `read` 打开 `path`，确认 `line` 附近的符号确实存在。
2. 用 `grep` 搜索调用方/被调用方，确认数据流：
   `入口/页面 → 组件 → 服务/API → 数据层`。
3. 检查是否有同名文件、生成代码、旧实现或 feature flag。
4. 若行号漂移，以实际内容为准，并在最终回复中更新为真实行号。

**禁止**只根据索引行号直接改代码；**禁止**臆造不存在的文件或函数。

### 第 4 步：低置信度时补定位

若 `confidence` 为「低」或 `files` 为空：

1. 让用户补充：目标页面/模块名、一个相关文件或函数名、期望行为。
2. 用 `glob`/`grep` 搜索需求中的业务词、路由、接口路径、错误码。
3. 找到 1-2 个锚点文件后，把它写进 `--prompt` 再跑一次，例如：
   `给 src/pages/LoginPage.tsx 的登录表单加记住我`。
4. 仍找不到时，明确告诉用户「当前项目没有匹配到承载该需求的代码」，不要硬编。

### 第 5 步：把结果当作任务书执行

生成提示词后：

1. 以其中的「需求（规范化）」「代码定位」「实施约束」「验收标准」为准。
2. 保持原意：提示词是规范化，不是扩写需求；不要添加用户没要求的产品行为。
3. 若提示词与代码现状冲突（例如文件已删除、接口已改名），先说明冲突，再调整。
4. 完成后按「验证命令」实际运行，并在回复中给出命令与结果。
5. 检查生成的提示词是否意外带出密钥、token、个人数据；如有，删除后再使用。

## 输出结构

生成的提示词固定包含：

1. **执行摘要**：需求类型、置信度、首选修改点、技术栈。
2. **项目框架**：语言、框架、入口、命令、关键目录、文档。
3. **需求（规范化）**：目标、范围、不在范围。
4. **代码定位**：按优先级排列的 `文件:行`、角色、依据、建议动作。
5. **关键代码证据**：候选文件的目标行附近片段。
6. **实施约束**：复用现有模式、最小 diff、UI/API/DB 专项约束。
7. **实施步骤**：阅读 → 定位 → 实现 → 测试 → 验证。
8. **验收标准**：按意图生成的可勾选清单。
9. **验证命令**：项目真实可用的命令，而不是泛泛的 `npm test`。
10. **待确认**：只在低置信度或提问句式时出现。
11. **给执行 AI 的提示**：先读后改、最小 diff、回复结构。
12. **原始需求**：保留原话，便于对照。

## UI 按钮（可选）

本技能包同时是一个 DSH 插件包：

- 宿主插件注册 `POST /api/xian/optimize-stream`、`POST /api/xian/optimize`、`POST /api/xian/insight`、`GET /api/xian/asset` 与 `GET /api/xian/health`。
- 客户端插件在输入框右侧（`conversation.input.right`）加「✦ Xian优化」按钮，并在右下角常驻角色挂件。
- 挂件主动调用 `/api/xian/insight` 展示项目理解程度、覆盖率、框架/入口等参数；可切换快速/标准/深度/极致四档优化深度。
- 点击优化后流式显示扫描/生成进度，完成后打开预览窗；可复制或确认后替换输入框。

安装与卸载见 `README.md` 的「安装输入框按钮」。按钮不可用时，CLI 仍然完全可用。

## 设计原则

- **离线优先**：不调用 LLM、不联网、不上传代码；只读扫描项目。
- **确定性**：同样的需求与项目，输出稳定，便于比较和回归。
- **证据优先**：每个定位都带路径、行号、符号或内容命中依据。
- **区分角色**：primary 是要改的，likely 待确认，reference 是参考，test 是测试，config 是配置。
- **诚实**：低置信度、索引截断、无匹配都会写进 `warnings`，不假装精准。
- **最小侵入**：不写项目文件、不改配置、不执行项目代码；索引缓存只在进程内存中保留 30 秒。

## 故障排查

| 现象 | 处理 |
| --- | --- |
| `项目路径不存在` | 检查 `--root`；Windows 路径用引号包裹 |
| `未找到与需求直接匹配的文件` | 补充模块名/页面名/函数名，或先用 `grep` 找锚点 |
| 结果里全是 `node_modules` | 不会发生；扫描器默认跳过依赖、构建产物、缓存 |
| 结果里没有测试 | 项目可能没有测试框架，或测试在默认跳过目录中 |
| 文件数达到上限 | 用 `--max-files` 提高（最多 20000）或缩小 `--root` |
| 输出被截断 | 提高 `--max-chars`，或减少 `--max-files` |
| 按钮 404 | 宿主插件未安装/未重启；按 README 安装后重启 DSH |
| 按钮报「cwd」错误 | 当前会话没有工作区；先选择/打开一个项目 |
